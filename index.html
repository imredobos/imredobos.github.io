Overview Widget iframe

Hello Tamas — a cross-origin host page for the two ways of putting a Zocks booking page on somebody else's site, one per page so they can be compared against each other.

Widget

Loads /embed/v1.js and calls Zocks.initWidget() twice: once inline, once as a popup. The host page gets onReady, onResize, onStepChange, onBookingConfirmed and onError back.

Open /widget →

iframe

A plain <iframe> pointing straight at the booking page. No script on the host page, and no visibility into what happens inside the frame.

Open /iframe →

What both pages point at

Everything is configured by the booking page link itself. The default lives in assets/config.js; either page accepts ?url=, so one deploy can demo any booking page — an advisor link, an event-type link, or (once the pages ship) a firm-wide /zocks link, with ?l= scheduling links carried through. Branding overrides are supported too — ?brandColor=%23b91c1c, ?hideLogo=1, ?hideAccountName=1, ?hideProfilePhoto=1, ?hideUserName=1, or ?hideAll=1 for all four at once; an explicit flag wins over hideAll, so ?hideAll=1&hideLogo=0 hides everything but the logo. Hide-only plus a recolor: a param can undo the host's own hideAll, but never show or replace what the account's settings keep private.

No allowlist, no setup

Booking pages answer frame-ancestors 'self' *, so any site — this one included — can embed them with zero configuration. If the frame still never renders (a wrong link, or a booking site not yet running the embedding release), /widget degrades to its own "Open the booking page" link after its 4s timeout, while /iframe shows only the browser's blocked-frame error — which is the comparison the two pages exist to make.

For a local app, point the demos at it with ?url=http://localhost:3000/<account>/<user>.
